# Проверка кассовых операций по видео

Веб-сервис для кейса ForteBank Datathon 26. Он принимает `.mov`, запускает локальный анализ в отдельном процессе и возвращает результат по API жюри. Модель распознавания подключается отдельно; пока она не подключена, задание получает статус `failed`, а не ложный вердикт `no_violation`.

## Что уже работает

- Локальный экран входа и инвентарь в стиле Minecraft: выбор `.mov`, работа с X-API ключом, справочник, настройки и создание Ока Эндера.
- Отдельная веб-страница `/review` для загрузки, просмотра статуса, таймкодов и кадров.
- Локальное превью выбранного видео и переход к моменту события по таймкоду, если браузер поддерживает кодек файла.
- `POST /api/v1/analyze` и `GET /api/v1/jobs/{job_id}` с заголовком `X-API-Key`.
- Очередь из одного задания, сохранение статусов в SQLite и восстановление очереди после перезапуска.
- Отдельный процесс на каждое видео с ограничением времени обработки.
- Проверка формата имени и размера загрузки; удаление исходного видео после обработки и результата через заданный срок.
- Формирование JPEG-кадров и JSON по схеме кейса из результата модели.

## Быстрый запуск

Нужны Python 3.12+ и доступ к сети **только при установке** зависимостей и весов модели.

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
```

Создайте `.env` по образцу `.env.example`, задайте случайный `API_KEY` и путь к модели в `ANALYZER_ENTRYPOINT`. Запустить сервис с этим файлом можно так:

```bash
uvicorn app.main:app --env-file .env --host 0.0.0.0 --port 8000 --workers 1
```

Или задайте переменные окружения напрямую, например в PowerShell:

```powershell
$env:API_KEY = "длинный-случайный-ключ"
$env:ANALYZER_ENTRYPOINT = "my_model.adapter:analyze_video"
uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 1
```

Откройте `http://localhost:8000`: сначала появится экран входа по X-API ключу. После проверки ключа откроется инвентарь `/app`. Эндер-жемчуг выбирает видео, огненный порошок помещает ключ в ячейку создания, огненный стержень меняет ключ. Клавиши `1`–`9` выбирают соответствующий слот нижнего ряда; кнопка книги открывает справочник, где зелёный переключатель показывает все действия. Когда выбраны файл и ключ, появится Око Эндера. Его следующий экран пока не реализован: существующая страница анализа доступна отдельно по `/review` и не была изменена. Сам анализ видео не делает сетевых запросов; веса модели должны быть загружены заранее.

Для локальной проверки интро можно временно задать `DEMO_KEY_ENABLED=1` в `.env`. Тогда ключ `test` принимается API наряду с обычным ключом. Эта настройка по умолчанию выключена; перед подключением модели и публичной демонстрацией уберите её или задайте `0`.

Для **личного просмотра на этом ПК** экран входа и инвентарь используют настоящую панораму, текстуры и bitmap-символы из установленного Minecraft. Не запуская игру, выполните `python scripts/extract_local_panorama.py` (при желании выберите индекс через `--index 5.json`), `python scripts/extract_local_minecraft_font.py` и `python scripts/extract_local_inventory_assets.py`. Чтобы поставить свой игровой скриншот за инвентарём, последнюю команду можно выполнить с `--world-reference "путь/к/изображению.png"`. Скрипты копируют исходные игровые файлы в исключённую из Git папку `app/static/minecraft-local/`. Эти изображения и шрифт не входят в публичный репозиторий и Docker-образ; без них инвентарь не будет выглядеть как в Minecraft. Перед публичной демонстрацией замените игровые материалы на те, права на которые позволяют использование в проекте ForteBank.

Значки предметов устанавливаются отдельно командой `python scripts/fetch_inventory_item_icons.py`: это готовые прозрачные PNG, захваченные в игре из набора [Minecraft Item Gallery](https://github.com/TinyTank800/MinecraftAllImages), версия 1.21.1 (Enhanced). Скрипт использует закреплённую ревизию источника и сохраняет изображения без изменений в локальную папку `minecraft-local/inventory/items/`. Один набор используется в нижнем ряду, справочнике, анимации и ячейках создания. Книга, фильтр и пустые ячейки экипировки используют оригинальные GUI-спрайты из установленной игры.

## API

```bash
curl -X POST http://localhost:8000/api/v1/analyze \
  -H "X-API-Key: <ключ>" -F "file=@clip.mov"
```

`POST` отвечает `202` и `{"job_id":"..."}`. Затем опрашивайте `GET /api/v1/jobs/{job_id}` с тем же ключом. Пока задание в очереди или выполняется, возвращается `status: "processing"`. После завершения — `status: "done"`, `verdict: "violation" | "no_violation"` и массив `violations`. При ошибке — `status: "failed"` и `error`. Кадры в `evidence_frames` — JPEG в base64. Жюри должно получить итог не позднее пяти минут после загрузки.

API жюри не содержит отдельного поля для нормативного источника, поэтому сервис добавляет название документа и пункт в `description`. В интерфейсе источник также показан ссылкой.

## Подключение модели

Смотрите [контракт анализатора](docs/MODEL_INTEGRATION.md). После подключения проверьте `GET /healthz`: `ready` станет `true`. Правила в `app/rules.json` — проверенные кандидаты для MVP, их нужно сверить с фактическим датасетом и дополнить подходящими категориями.

Полный архив из 42 роликов и его метки прошли локальную [проверку набора](docs/DATASET.md). Это проверка формата и сервиса, а не точности распознавания. См. также [карту нормативных кандидатов](docs/NORMATIVE_MAPPING.md), [архитектуру](docs/ARCHITECTURE.md) и [подготовку к сдаче](docs/SUBMISSION.md).

## Проверка

```bash
pip install -r requirements-dev.txt
pytest -q
```

Перед сдачей прогоните самый длинный ролик на том же оборудовании, где будет работать публичный сервис. Лимит задания по умолчанию — 270 секунд, чтобы оставить время для загрузки и выдачи ответа в пределах пяти минут.

Для проверки архива используйте `python scripts/audit_dataset.py --archive /path/to/open.zip`; для измерения декодирования — `python scripts/benchmark_decode.py /path/to/video.mov`. После подключения модели задайте `API_KEY` в окружении и запустите `python scripts/evaluate_api.py`. Отчёты сохраняются в исключённом из Git каталоге `data/`.

## Развёртывание

```bash
docker build -t forte-video-review .
docker run -d --name forte-video-review -p 8000:8000 \
  -e API_KEY="<случайный-ключ>" \
  -e ANALYZER_ENTRYPOINT="my_model.adapter:analyze_video" \
  -v forte-data:/service/data forte-video-review
```

Код модели и веса нужно добавить в образ или примонтировать отдельно; приведённая команда показывает только каркас сервиса. Запускайте один процесс сервера (`--workers 1`), поскольку он управляет локальной очередью. При необходимости можно увеличить `PARALLEL_JOBS`, предварительно проверив память и скорость модели. Не передавайте тестовые видео внешним сервисам. Исходные файлы удаляются сразу после обработки, а результаты с кадрами — через `RESULT_TTL_HOURS` (по умолчанию 24 часа).
