# Проверка кассовых операций по видео

Веб-сервис для кейса ForteBank Datathon 26. Он принимает `.mov`, запускает локальный анализ в отдельном процессе и возвращает результат по API жюри. Из `oko.zip` интегрирован реальный базовый детектор обзора камеры. Полная модель кассовых действий подключается отдельно; интерфейс явно показывает ограниченный охват базового детектора. Подробнее: [интеграция OKO](docs/OKO_INTEGRATION.md).

## Что уже работает

- Локальный экран входа и инвентарь в стиле Minecraft: выбор `.mov`, работа с X-API ключом, справочник, настройки и создание Ока Эндера.
- Экран Энда `/review` автоматически получает запись и ключ из инвентаря и начинает анализ при подключённой модели. Игровой фон, видео, полоса обработки, отчёт с двумя вердиктами, событиями, таймкодами, кадрами и нормативными ссылками. Повторного выбора файла и ключа в Энде нет.
- Восстановление задания после обновления страницы, понятные ошибки, справочник правил и скачивание ответа API в JSON.
- Локальное превью выбранного видео и переход к моменту события по таймкоду, если браузер поддерживает кодек файла.
- `POST /api/v1/analyze` и `GET /api/v1/jobs/{job_id}` с заголовком `X-API-Key`.
- Очередь из одного задания, сохранение статусов в SQLite и восстановление очереди после перезапуска.
- Отдельный процесс на каждое видео с ограничением времени обработки.
- Проверка формата имени и размера загрузки; удаление исходного видео после обработки и результата через заданный срок.
- Формирование JPEG-кадров и JSON по схеме кейса из результата модели.
- Minecraft-плеер с перемоткой, скоростью, громкостью, полным экраном, активностью и миниатюрами; игровые звуки и переход через портал.
- Видимая диагностика подключения, расширенный каталог OKO с поиском, сомнительные эпизоды отдельно от вердикта, автономный HTML-отчёт.

## Запуск на другом компьютере

Нужен Python 3.12+. Скачайте репозиторий целиком через **Code → Download ZIP** и распакуйте его, либо выполните `git clone https://github.com/AmirBro0/2.git`. Откройте терминал в папке проекта. На существующей копии достаточно выполнить `git pull`.

**Windows:**

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run_local.py
```

**Linux / macOS:**

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run_local.py
```

Откройте **http://127.0.0.1:8000/** и введите **`test`**. При первом запуске `run_local.py` создаст `.env` со случайным личным ключом, включённым временным входом `test` и базовым анализатором OKO. Если `.env` уже есть, скрипт сохраняет его настройки. Для другого порта: `python run_local.py --port 8001`. Остановка — `Ctrl+C`.

**Все фоны, панорама, изображения предметов, персонаж, шрифты и звуки уже включены в проект.** Установленный Minecraft и исходный компьютер не нужны. Ресурсы раздаются самим приложением; внешние сайты для интерфейса не используются. Интернет нужен при скачивании проекта и установке зависимостей. Полную модель коллеги и её веса подключают отдельно.

## Ручная настройка запуска

Создайте `.env` по образцу `.env.example`, задайте случайный `API_KEY`. В примере уже выбран локальный базовый детектор OKO. Для модели коллеги замените `ANALYZER_ENTRYPOINT`. Запустить сервис с этим файлом можно так:

```bash
uvicorn app.main:app --env-file .env --host 127.0.0.1 --port 8000 --workers 1
```

Или задайте переменные окружения напрямую, например в PowerShell:

```powershell
$env:API_KEY = "длинный-случайный-ключ"
$env:ANALYZER_ENTRYPOINT = "my_model.adapter:analyze_video"
uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

Откройте `http://localhost:8000`: ключ проверяется на стартовом экране, затем открывается инвентарь `/app`. Эндер-жемчуг выбирает видео, порошок добавляет проверенный ключ в создание, стержень меняет ключ. Клавиши `1`–`9` выбирают слот; книга открывает справочник. Око переносит готовую запись и ключ в Энд `/review`, где проверка запускается автоматически при готовой модели. После завершения можно перейти к таймкоду, увеличить кадр, открыть нормативный источник и скачать JSON. При отсутствии модели показываются запись и ожидание; проверка подключения продолжает работу с теми же данными. Сам анализ не делает сетевых запросов.

Текущий файл хранится в IndexedDB и восстанавливается после обновления страницы и возвращения в инвентарь. Срок записи — час после последнего обращения; истёкшие записи удаляются при следующем чтении или сохранении. Выбор нового файла заменяет прежний. Ключ остаётся в sessionStorage текущей вкладки и не включается в URL, отчёты или IndexedDB. Задание связано с идентификатором текущего файла; готовый отчёт восстанавливается без повторной отправки. Прямой вход в Энд без созданного Ока предлагает только возврат в инвентарь.

Для локальной проверки интро можно временно задать `DEMO_KEY_ENABLED=1` в `.env`. Тогда ключ `test` принимается API наряду с обычным ключом. Эта настройка по умолчанию выключена; перед подключением модели и публичной демонстрацией уберите её или задайте `0`.

## Ресурсы интерфейса

Папка `app/static/minecraft-local/` хранится в Git и включается в Docker-образ. Название папки историческое: она больше не зависит от локальной установки игры. В ней находятся шесть сторон панорамы, фон инвентаря и Энда, PNG предметов, GUI-текстуры, bitmap-символы с кириллицей, готовый TTF и звуки. Изображение персонажа находится в `app/static/character-art.png`.

Источники ресурсов описаны в [ASSETS.md](docs/ASSETS.md). Скрипты `extract_local_*.py`, `fetch_inventory_item_icons.py`, `fetch_end_background.py` и `build_local_minecraft_font.py` оставлены для обновления ресурсов разработчиком; **для обычного запуска выполнять их не нужно**. При обновлении извлечённые файлы также коммитят в репозиторий.

Звуки включаются кнопкой в нижнем левом углу. Последовательность экранов закреплена в `AGENTS.md`. Ключи `.env`, загруженные банковские видео, результаты обработки и веса моделей не включаются в репозиторий.

## API

```bash
curl -X POST http://localhost:8000/api/v1/analyze \
  -H "X-API-Key: <ключ>" -F "file=@clip.mov"
```

`POST` отвечает `202` и `{"job_id":"..."}`. Затем опрашивайте `GET /api/v1/jobs/{job_id}` с тем же ключом. Пока задание в очереди или выполняется, возвращается `status: "processing"`. После завершения — `status: "done"`, `verdict: "violation" | "no_violation"` и массив `violations`. При ошибке — `status: "failed"` и `error`. Кадры в `evidence_frames` — JPEG в base64. Жюри должно получить итог не позднее пяти минут после загрузки.

API жюри не содержит отдельного поля для нормативного источника, поэтому сервис добавляет название документа и пункт в `description`. В интерфейсе источник также показан ссылкой.

## Подключение модели

Смотрите [контракт анализатора](docs/MODEL_INTEGRATION.md). После подключения проверьте `GET /healthz`: `ready` станет `true`. Правила в `app/rules.json` — проверенные кандидаты для MVP, их нужно сверить с фактическим датасетом и дополнить подходящими категориями.

Полный архив из 42 роликов и его метки прошли локальную [проверку набора](docs/DATASET.md). Это проверка формата и сервиса, а не точности распознавания. См. также [карту нормативных кандидатов](docs/NORMATIVE_MAPPING.md), [архитектуру](docs/ARCHITECTURE.md) и [подготовку к сдаче](docs/SUBMISSION.md).

## Проверка

```bash
pip install -r requirements-dev.txt
pytest -q
```

Перед сдачей прогоните самый длинный ролик на том же оборудовании, где будет работать публичный сервис. Лимит задания по умолчанию — 270 секунд, чтобы оставить время для загрузки и выдачи ответа в пределах пяти минут.

Для проверки архива используйте `python scripts/audit_dataset.py --archive /path/to/open.zip`; для измерения декодирования — `python scripts/benchmark_decode.py /path/to/video.mov`. После подключения модели задайте `API_KEY` в окружении и запустите `python scripts/evaluate_api.py`. Отчёты сохраняются в исключённом из Git каталоге `data/`.

## Развёртывание

```bash
docker build -t forte-video-review .
docker run -d --name forte-video-review -p 8000:8000 \
  -e API_KEY="<случайный-ключ>" \
  -e ANALYZER_ENTRYPOINT="my_model.adapter:analyze_video" \
  -v forte-data:/service/data forte-video-review
```

Код модели и веса нужно добавить в образ или примонтировать отдельно; приведённая команда показывает только каркас сервиса. Запускайте один процесс сервера (`--workers 1`), поскольку он управляет локальной очередью. При необходимости можно увеличить `PARALLEL_JOBS`, предварительно проверив память и скорость модели. Не передавайте тестовые видео внешним сервисам. Исходные файлы удаляются сразу после обработки, а результаты с кадрами — через `RESULT_TTL_HOURS` (по умолчанию 24 часа).
