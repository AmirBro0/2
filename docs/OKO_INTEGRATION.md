# Интеграция OKO

Источник: переданный пользователем `oko.zip`. Код конвейера перенесён в `app/oko` и адаптирован для существующего FastAPI-сервиса. Отдельный сервер OKO запускать не нужно.

## Что работает

- Реальный локальный детектор `obstruction`: падение детализации и тёмные/однотонные участки, объединение последовательных срабатываний. Это эвристика обзора камеры, не обученная модель кассовых операций.
- Отдельные оценки выше `OKO_THRESHOLD` и кандидаты для человека между `OKO_REVIEW_THRESHOLD` и основным порогом.
- 1–3 кадра с таймкодами, рамки при наличии координат от детектора, пикселизация обнаруженных лиц на кадрах отчёта. Личности не устанавливаются; обнаружение лиц для пикселизации не гарантирует нахождение каждого лица.
- Покадровый ход обработки, место в очереди, время, охват записи, активность и миниатюры на шкале плеера.
- Каталог 21 типа событий OKO, включая открытый класс X00, плюс прежний каталог проекта. Поля сверки норм унаследованы из архива; наличие пункта не доказывает применимость к конкретному событию. Для V13 в официальной редакции НБ-14, п. 16 подп. 6), есть требование оборудования кассы камерами: https://old.adilet.zan.kz/rus/docs/V2400035552.
- Просмотр сомнительных эпизодов отдельно от вердикта, JSON по схеме API и автономный HTML-отчёт с кадрами.

## Подключение

В `.env`:

```dotenv
ANALYZER_ENTRYPOINT=app.analyzers.oko:analyze_video
OKO_DETECTORS=obstruction
OKO_SAMPLE_FPS=5
OKO_THRESHOLD=0.65
OKO_REVIEW_THRESHOLD=0.3
```

`test` остаётся временным ключом localhost при `DEMO_KEY_ENABLED=1`. Когда подключается модель коллеги, отключите demo-ключ. Его компьютер не нужен для встроенного детектора: он работает на машине, где запущен этот сервис.

Расширение: класс `Detector` в `app/oko/pipeline/detectors`, регистрация в `REGISTRY`, затем имя в `OKO_DETECTORS`. Заготовка VLM сохранена, но не включена. Старый контракт `ANALYZER_ENTRYPOINT=module:function` с перечнем наблюдений также работает.

## API и надёжность

- `/api/v1/connection`: сервер, проверка текущего ключа, загрузка анализатора и конкретная причина недоступности. Требует X-API-Key.
- `/api/v1/jobs/{id}` сохраняет прежнюю схему для жюри.
- `/api/v1/jobs/{id}/details` содержит расширенные данные OKO; также требует ключ.
- Используется существующая очередь SQLite с восстановлением после перезапуска и отдельным процессом на видео. Дедлайн включает ожидание очереди.
- Пустой реестр, неизвестный детектор, сбой детектора, отсутствие кадров и неполный охват завершают задание ошибкой, а не вердиктом «нарушение не обнаружено».
- Демонстрационный детектор и генерация фиктивных результатов из OKO не включены. Файлы/кадры не отправляются внешним AI-сервисам.

## Интерфейс

Сохранён путь `/` → `/app` → `/review`: ключ и файл вводятся только на первых двух экранах. В Энде нет повторного выбора. Плеер: пробел, стрелки ±5 с, M, F, громкость, скорость, миниатюры и отметки событий. Запоминается позиция текущей записи. Звуки оригинального Minecraft включаются кнопкой «Звуки» и по умолчанию выключены. Все игровые ресурсы включены в репозиторий и Docker-образ. `scripts/extract_local_ui_assets.py` нужен только для их обновления; установленный Minecraft для запуска сайта не требуется.

Проверки: `python -m pytest -q`; UI — искусственные записи с перекрытым и открытым изображением, полный переход через инвентарь, восстановление отчёта без повторной загрузки, элементы управления плеером и диагностика подключения.
