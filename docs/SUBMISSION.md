# Подготовка к проверке жюри

## Что уже подготовлено

- Веб-интерфейс для `.mov`, статус обработки, таймкоды, кадры и нормативные ссылки.
- Двухшаговый API с `X-API-Key` по разделу 10 задания.
- Локальная очередь, удаление исходных файлов после обработки, лимит времени задания.
- [Аудит набора и проверка API](DATASET.md), [карта нормативных кандидатов](NORMATIVE_MAPPING.md), [архитектура](ARCHITECTURE.md).

## Что необходимо завершить перед сдачей

1. Подключить локальный анализатор и веса, записать фактически используемые модели и лицензии. Убедиться, что все нужные файлы доступны без интернета во время анализа.
2. Прогнать весь размеченный набор через `scripts/evaluate_api.py`, проверить ложные срабатывания, пропуски, таймкоды и релевантность кадров вручную. Дубликаты учитывать отдельно.
3. Замерить полный запрос на ролике `Х-14.mov` (142,533 секунды, 28 718 927 байт) на машине демонстрации. Проверить, что результат доступен через API менее чем за пять минут, включая загрузку и очередь. На текущем ПК чтение всех 4273 кадров без модели заняло около 7,4 секунды; это не итоговый замер.
4. Получить устойчивый публичный HTTPS-адрес сервиса и API. Сейчас сервис доступен только на `127.0.0.1:8000`; для внешнего доступа нужна работающая машина и сетевой маршрут к ней. Адрес должен оставаться доступным во время проверки жюри.
5. Создать отдельный ключ для жюри, проверить отказ без ключа, затем передать жюри адрес интерфейса, адрес API и ключ. Не публиковать `.env` и не включать обучающие или тестовые видео в репозиторий.
6. В итоговом описании указать только категории, которые реально распознаются, и известные ограничения по ракурсу и неоднозначным событиям. Удалить данные после окончания разрешённого периода использования.

## Проверка запуска

```bash
pip install -r requirements-dev.txt
pytest -q
python scripts/audit_dataset.py --archive /path/to/open.zip
```

Запуск самого сервиса описан в [README](../README.md). После подключения модели запустите `scripts/evaluate_api.py` с `API_KEY` в переменной окружения и проверьте `GET /healthz`. Не считайте `ready: true` доказательством качества модели: оно означает лишь, что задано имя адаптера.

## Ограничения текущей версии

- Модель отсутствует, поэтому вердикты и метрики качества пока недоступны.
- Метки обучающего архива не содержат типа события; точность классификации типа требует отдельной ручной проверки.
- Все 42 исходных ролика имеют один ракурс. Устойчивость к другой камере из них не измерить.
- `Х-4` и `Х-47` — одинаковый файл с разными помеченными секундами; это неоднозначность исходной разметки.
- Браузер может не воспроизвести кодек некоторых `.mov`; API и извлечение JPEG работают независимо от браузерного превью.
- Docker-образ на текущем Windows-компьютере не проверен, поскольку Docker здесь не установлен. Локальный запуск Python проверен.
