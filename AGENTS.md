# Согласованный пользовательский сценарий

- Интерфейс является последовательным Minecraft-сценарием: `/` (проверка ключа) → `/app` (инвентарь и создание Ока) → `/review` (Энд, анализ и результат).
- Файл выбирают эндер-жемчугом в инвентаре. Порошок добавляет уже проверенный ключ; стержень возвращает на `/` для выбора другого ключа. При этом файл сохраняется, старый ключ и готовность Ока сбрасываются; отдельное окно ввода ключа в инвентаре не показывать.
- Око переносит выбранный файл и ключ в Энд автоматически. В Энде запрещены повторные поля ключа, выбор или перетаскивание файлов, повторное создание Ока и второй инвентарь. Не добавлять их как удобный запасной путь.
- Обновление Энда и возврат в инвентарь сохраняют текущую запись. Готовый отчёт восстанавливается по тому же заданию, без повторной отправки файла. Отчёт должен принадлежать текущей записи.
- Энд показывает полученное видео, ход проверки и результат. При готовой модели проверка запускается автоматически после Ока. При отсутствии модели показывается честное ожидание. Прямой вход без контекста предлагает вернуться в инвентарь.
- Пользователь отверг обычный веб-дашборд, большой серый контейнер с дублирующими формами и повторным хотбаром. Сохранять игровой характер: реальные Minecraft-изображения, оригинальные локальные спрайты, пиксельный шрифт, игровые кнопки и подсказки. Не генерировать имитации игровых картинок. Игру не запускать.
- Назначение головы дракона в инвентаре пока не определено пользователем. Не назначать ей новую функцию самовольно.
- Важные проверки UI: вход → выбор файла → порошок → Око; файл и ключ появились автоматически; нет элементов повторного выбора; refresh сохраняет запись; возврат восстанавливает инвентарь; отчёт после refresh не отправляет видео заново.
- Сейчас только localhost. Модель готовит коллега. Временный ключ `test` сохраняется до подключения модели, затем demo-режим нужно отключить.
- Не подменять отсутствие модели успешным результатом. Тестировать интерфейс результатов искусственными роликами и отдельным тестовым анализатором.
- Интегрирован `oko.zip`: реальный локальный детектор `obstruction` проверяет только обзор камеры. Всегда показывать эту границу рядом с проверкой и в отчёте. Полную модель кассовых действий пока готовит коллега. Демо-детектор не подключать.
- «Проверить подключение» открывает видимую диагностику сервера, текущего ключа и анализатора; действие всегда должно иметь понятный отклик.
- Плеер имеет собственные Minecraft-кнопки и полосу опыта; не возвращать стандартную панель управления браузера.
- Проект должен переноситься на другой ПК вместе со всеми ресурсами интерфейса. Папка `app/static/minecraft-local/` входит в Git и Docker: фоны, панорама, шрифт, предметы, текстуры и звуки. Для запуска не требовать установленный Minecraft, файлы из Downloads или повторное извлечение ресурсов. Секреты `.env`, банковские видео, результаты и веса модели остаются вне Git.
